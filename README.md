# Учебный портал колледжа

Закрытая площадка для одного преподавателя и его групп: лекции и практические,
доступ к которым выдаётся поимённо подгруппам, и журнал посещаемости и оценок.

Ключевое отличие от «выложить материалы в общую папку»: **материал не виден
никому по умолчанию**. Тема становится видимой только после того, как её
открыли конкретной подгруппе с конкретной даты.

---

## Что уже работает

**Вход.** Логин и пароль — либо одноразовый код первого входа, поле одно.
Почты в системе нет вообще: студентов заводит преподаватель, он же выдаёт коды
и сбрасывает доступ. Пять неудачных попыток блокируют вход на 15 минут.

**Преподаватель.** Группы и подгруппы. Массовое заведение студентов из списка
ФИО — логины генерируются транслитом, коды выдаются печатной таблицей.
Дисциплины, темы двух типов (лекция и практическая), содержание и задание
текстом, материалы файлами, выдача темы подгруппам с датами открытия
и закрытия.

**Студент.** Список открытых тем по дисциплинам со статусами и сроками,
страница темы с материалами по коротким подписанным ссылкам.

**Чего ещё нет.** Журнала: посещаемости, сдачи работ, оценок и пересдач.
Тестов с автопроверкой. Мобильная вёрстка не доводилась.

## Быстрый старт

```bash
npm install          # postinstall сам вызовет prisma generate
npm run setup:env    # создаст .env.local со случайным секретом и паролем
npm run db:up        # локальный Postgres — ОТДЕЛЬНОЕ окно терминала
```

`db:up` держит базу, пока работает, — как `next dev`. Дальше во втором окне:

```bash
npm run db:migrate   # создаст таблицы
npm run db:seed      # аккаунт преподавателя и две дисциплины
npm run dev
```

Логин и пароль преподавателя печатает `setup:env`; они же лежат в `.env.local`.
Смените пароль до того, как в системе появятся студенты.

Состояние окружения видно на `/setup` — база, хранилище, секрет сессий.
Страница открыта, пока в базе нет ни одного пользователя, и закрывается на
преподавателя сразу после сида.

### Откуда берётся Postgres

Из `node_modules`: пакет `embedded-postgres` кладёт готовые бинарники, данные
живут в `.pgdata` внутри проекта. Ничего не ставится в систему, прав
администратора не нужно, удаляется вместе с папкой.

Это решение на время разработки. Альтернативы без правок кода: Docker
(`npm run db:up:docker`, `docker-compose.yml` в корне) или любой установленный
Postgres — `npm run setup:env -- --port 5432 --user postgres --password пароль`.

## Переменные окружения

| Переменная | Локально | На боевой базе |
|---|---|---|
| `DATABASE_URL` | Postgres из `db:up` | хост **с** `-pooler`. Читает приложение |
| `DIRECT_URL` | та же строка | хост **без** `-pooler`. Читает `prisma.config.ts`, нужен миграциям |
| `AUTH_SECRET` | генерируется | сделать новый, не меньше 32 символов |
| `R2_*` | можно оставить пустыми | Cloudflare R2: Account ID и токен с правами Object Read & Write |
| `TEACHER_*` | для `db:seed` | не нужны |

Разделение pooled/direct существует только там, где перед базой стоит
pgBouncer. Локально пулера нет, поэтому обе строки одинаковые.

## Как устроен доступ

Видимость темы задаёт одна запись — `TopicRelease` (тема × подгруппа × даты).
Нет записи — темы для этой подгруппы не существует.

Проверка живёт в одном месте, `src/lib/access.ts`, и повторяется при каждом
обращении, включая выдачу ссылки на файл. Закрытая тема отдаёт **404, а не
403**: иначе перебором идентификаторов можно узнать, какие темы вообще есть.

Отдельно стоит помнить, что Server Actions — это публичные HTTP-эндпоинты.
Отсутствие кнопки в интерфейсе не защищает ничего, поэтому фильтрации на
клиенте в проекте нет нигде.

## Решения, которые стоит знать до правок

**Файлы не проходят через API.** На Vercel тело запроса к функции ограничено
4.5 МБ, и это не настраивается, а презентация с картинками весит втрое больше.
Схема в `src/lib/storage.ts`: браузер просит подпись → кладёт файл прямо
в хранилище → сервер проверяет `HEAD` и только тогда создаёт запись. Ссылки
на скачивание живут пять минут — переслать можно, но к следующей паре
протухнет.

**Одно соединение на функцию.** `src/lib/prisma.ts` — синглтон через
`globalThis` (иначе hot-reload в разработке накапливает клиентов) и `max: 1`
в адаптере: настоящий пул держит pgBouncer на стороне базы.

**Оценки привязаны к занятию, а не к теме.** Одна тема идёт у четырёх
подгрупп в четыре разные даты, и журнал читается по датам. Отсюда отдельная
сущность `ClassSession`.

**Оценки не перезаписываются.** Пересдача — новая запись с номером попытки.
Итог считается по правилу дисциплины: последняя попытка или лучшая.

**Коды первого входа хешируются HMAC-SHA256, а не bcrypt.** Импорт подгруппы
— это 25–30 кодов в одном запросе, и bcrypt добавил бы по ~300 мс на каждый.
По существу это тоже верно: код — случайный токен на 30 бит со сроком жизни
две недели, а не выбранный человеком пароль. Пароли остались на bcrypt.
В базе кода нет ни в каком читаемом виде: он показывается один раз, при
импорте.

**Содержание лекции выводится как HTML, без санитизации.** Единственный автор
в системе — преподаватель, студенты в эти поля не пишут никогда. Условие, при
котором это перестаёт быть безопасным, ровно одно: если содержание темы
сможет править кто-то ещё. Тогда нужна санитизация в
`src/app/study/[topicId]/page.tsx`.

## Структура

```
prisma/schema.prisma     модель данных целиком, с комментариями почему так
prisma/seed.ts           преподаватель и дисциплины по умолчанию
prisma.config.ts         конфиг Prisma 7: строки подключения здесь, не в схеме

scripts/init-env.mjs     создание .env.local
scripts/db.mjs           локальный Postgres из node_modules
scripts/check-env.mjs    понятная ошибка вместо EACCES, если окружение пустое

src/proxy.ts             отсечка по роли (в Next 16 это бывший middleware)
src/app/setup/           состояние окружения, закрывается после сида
src/app/login/           вход: пароль или код первого входа
src/app/set-password/    обязательная смена пароля после входа по коду
src/app/admin/           преподаватель: занятия, темы, группы, студенты
src/app/api/materials/   скачивание: проверка прав → подписанная ссылка
src/app/study/           студент: открытые темы и материалы

src/lib/access.ts        ★ единственное место, где решается видимость
src/lib/storage.ts       ★ подписанные ссылки, файлы мимо сервера
src/lib/prisma.ts        клиент-синглтон + driver adapter
src/lib/auth.ts          кто в запросе, requireTeacher / requireStudent
src/lib/session*.ts      JWT в httpOnly-куке; session-token.ts edge-совместим
src/lib/password.ts      хеши паролей и кодов
src/lib/translit.ts      ФИО → логин
```

★ — обходить эти два модуля «по-быстрому» не стоит: на них держится вся
модель доступа.

## Хранилище файлов

Бакет должен быть **закрытым**: файлы отдаются только по подписанным ссылкам.
Публичный бакет обнуляет всю систему доступа — ссылку просто перешлют.

Загрузка идёт из браузера напрямую в хранилище, поэтому бакету нужен CORS.
Без него загрузка молча падает с нулевым статусом:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "https://ваш-домен"],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

Забытый домен в `AllowedOrigins` — самая частая причина «загрузка не работает,
а ошибки нет». Загрузчик этот случай распознаёт и пишет про CORS прямым
текстом.

## Деплой

1. Репозиторий на GitHub, импорт в Vercel.
2. Переменные из `.env.local` — в Project → Settings → Environment Variables,
   с боевыми значениями: pooled и прямая строки облачной базы, новый
   `AUTH_SECRET`, ключи хранилища.
3. Build command менять не нужно: в `package.json` он уже
   `prisma generate && next build`.
4. Первую миграцию на боевую базу накатить локально: `npm run db:deploy`
   с боевым `DIRECT_URL`.

## Стек

Next.js 16 (App Router), TypeScript, Tailwind 4, Prisma 7 с driver adapter
(`@prisma/adapter-pg`), PostgreSQL, S3-совместимое хранилище. Аутентификация
написана вручную на `jose` — провайдеров нет, флоу с одноразовым кодом
нетиповой, и готовая библиотека здесь только мешала бы.
